# 实时语音聊图与摄像头画面

入口是原账号扫码后的 WebUI“对话”页。无需更新 Mac 辅助功能权限，也无需等晚间整理。

当前默认对话已统一接入[本机 DeepSeek Harness Chat / Work](HARNESS-CHAT.md)：视觉模型作为 Harness 工具参与同一会话；以下图片直连模型接口仍供明确授权的接口调用使用。

## 使用

1. 点“上传图片聊”或“拍照聊”，看到当前图片后开启实时对话，直接提问。若实时对话已开启，上传后可直接开口，图片正在解码、准备或同步时会等待保存完成，不会悄悄用上一张图回答。
2. 在“生活记录”中选图或拍照，同样会设置当前图片；已有照片可点“聊这张图”，进入对话并开启麦克风。刷新页面后需要重新选定当前图片，登录态仍按原方式保持。
3. 点“开启摄像头”，允许浏览器相机权限即可看到本地预览。相机权限与预览就绪后，每次普通语音提问，在最终转写后保存一张当前画面，再把问句和该帧直接交给所选视觉模型。预览期间不会持续上传所有帧，也不会按视频帧率调用模型。
4. 回复按文字增量进入现有 TTS，开口即可打断。追问同一照片会继续附带它；更换照片会停止旧回复，后续一轮使用新照片。打开相机后，每次提问产生新的帧 ID。
5. “关闭摄像头”保留最后一张已保存图片用于追问；“结束看图”同时停止相机并移除当前视觉上下文。离开对话页、网页进入后台、退出账号或相机被系统断开时停止摄像头轨道。相机失效时不会悄悄拿旧预览帧冒充新画面。

当前识图模型沿用“生活记录”顶部的账号设置；切换设置对下一轮生效，已发出的请求固定使用其图片和模型。24 个可选 ID 的图片流式响应均通过实测，见 [流式验证](research/VISION-STREAM-VALIDATION.json)。普通文字对话和电脑 Agent 仍沿用原模型与路由。图片内容不会自动成为电脑执行指令。

## 即时回答与晚间记忆

即时回答直接发送“问句＋图片”，省去先生成描述、再做文字问答的双重模型往返。没有当前图片时走原文字／语音流程。AI 每轮只拿到实际提供的图片，不承诺持续监视场景或发现后续变化。

上传的照片、真正提问时使用的相机帧、最终语音转写和助手回复进入同一账号的生活记录；不保存整段麦克风原始音频或相机视频。夜间继续按 23:00 / Asia/Shanghai 默认设置，把当天照片和对话共同整理为摘要及有来源的记忆，再同步本机 Agent。

对话自动记录开关仍有效：关闭时不自动归档问答文字；用户主动保存的照片和提示中明确说明的提问画面仍会保存。停止播报、关闭相机、取消电脑任务是不同操作，不会互相冒充。

删除原始照片会移除保留对话里的该图片引用，保留对话文字，并撤回关联记忆及派生摘要。若照片在对话尚待同步时被删，待传对话会只保存文字，避免一个失效附件阻塞后续记录。

## 接口与安全

`POST /model/v1/chat/completions` 新增可选 `life_images: ["私有图片ID"]`（最多两张）。普通调用需要已登录用户会话；仅有 tasks 授权的设备 token 不获得生活照片权限。统一 Chat 的识图工具可携带 vision_task，只读取该设备正在执行且未取消的该轮中明确附带的图片，模型选择随轮次固定。服务端校验图片归属、读取私有 JPEG、选择账号配置的已验证模型，向上游发送标准图文消息，不向浏览器返回上游凭据，也不依赖携带 token 的图片 URL。`X-Vision-Model` 返回本轮实际模型。

外部调用方应自行保存其需要归档的用户对话；该模型接口不会把 Harness 内部模型调用、工具结果或中间思考自动写入生活记录。WebUI 已实现图片和问答的归档。相同附件通过稳定 ID 复用，打断沿用既有 turn generation、AbortController 和音频队列清空机制，迟到片段不进入新一轮。

## 借鉴来源及边界

[豆包增量调查](research/DOUBAO-LIVE-VISION.md)区分安装包静态观察与火山官方公开 RTC 方案。公开方案支持视频抽帧、图片随问题进入视觉 LLM，以及语音与视觉的混合编排；这支撑声笺本轮的实现选择。没有复制豆包私有代码，也未声称恢复其 App 的私有摄像头传输、AEC、抽帧频率或全套实时视频模型。

当前采用浏览器本地预览和按提问取帧，未接入火山 RTC / Seeduplex。手机端相机权限、音频路由、免提回声和切后台行为仍需要真机体验，浏览器模拟不等同手机验收。

## 2026-10-23 验证

- 当前 24 个可选 WorkBuddy ID 均返回图片 SSE 增量、正确图像回答及完成标记。小图探测中默认 GLM-5V Turbo 首字约 1.83 秒；这是上游文字首字，不包含手机上传、ASR、TTS 或声学链路。
- 真实公网用户接口：默认 GLM 首字约 2.26 秒，正确回答红圆和图中文字；同图追问识别蓝色方形；改选 Kimi 后实际响应头和识图结果匹配。即时回答时尚未创建任何每日整理任务。
- 随后把一张照片与三轮问答（七条记录）共同整理，成功形成带来源的记忆；跨账号访问被拒；删除照片后对话图片引用、照片文件和关联记忆撤回。独立测试账号已退出，测试记录已清理。
- Playwright 使用虚拟麦克风／摄像头验证：上传 ACK 门控、ASR→图片流式回答→早期播报、打断清空旧音频和迟到文本、同图追问、预览不上传、每次提问一帧、关闭摄像头释放轨道、清除视觉上下文、原图入口转入语音、账号退出隔离及手机宽度布局。使用模拟设备，没有启用用户真实摄像头。

运行：`.venv/bin/python -m pytest tests/test_visual_chat.py tests/test_life.py tests/test_core_providers.py`；`SHENGJIAN_UI_BROWSER=<Chrome路径> node scripts/smoke_visual_voice.cjs`。既有语音、生活记录和全量回归另行保留。
