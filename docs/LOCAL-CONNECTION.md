# 本机端口选择与服务身份

Mac 原生版和 Windows Tauri 版由操作系统分配本次可用端口。桌面进程从自己启动的子进程管道读取实际端口，不再先探测一个空闲端口、释放后再交给服务绑定。旧客户端手动指定端口时，先跳过已占用地址；绑定时发生抢占也继续尝试，最终可回退到系统分配端口。

绑定成功后还要验证本次服务：协议、PID、版本、实例 ID，以及绑定当前端口的随机挑战应答。桌面客户端每次调用先验证身份，再发送账号或操作参数；响应也检查实例 ID。随机挑战只发送随机数，配对密钥留在客户端和本机服务内部。错误页面、重定向、其他实例或旧挑战应答均不能视为声笺。Windows 单文件安装包兼容 PyInstaller 引导进程与实际服务子进程的 PID 差异。

macOS 的通配监听即使关闭地址复用，也可能被后来绑定 `127.0.0.1` 的监听遮住。因此声笺在同一端口自行占有本机精确地址，并将其请求交给同一个服务实例；局域网监听及原来的文件传输协议继续提供服务。Windows 使用独占地址选项，两个平台都不启用端口共享。

Mac 主窗口正常轮询时会重新验证身份。连接检查失败只显示本机连接错误，不把它说成公网断网，不自动重发写入或任务。只有自己启动的服务进程确实退出才尝试恢复，最多连续三次；单次请求失败不会杀掉正在工作的 Agent。进程退出时已有任务仍遵循原有取消确认与结果未知规则，不重复执行。

文件传输 URL 和中转连接使用本次实际端口。手机语音/Agent 的固定公网账号入口不依赖桌面本地端口，因此不需要因为本机端口变化而重新扫码登录。旧 `/health` 和带配对 key 的旧手机接口保持兼容，新实例校验对新桌面客户端生效。

验证包括：真实套接字占用、绑定竞态、晚到监听、同 PID/版本的另一实例、错误密钥、旧实例操作拒绝、旧客户端兼容；Swift 原生与真实 Python 服务的随机挑战互验；桌面网页拒绝错误页面、重定向、复制身份和旧挑战，并确保失败操作只提交一次。Windows 原生构建与单文件安装验收由 Windows CI 执行；在 Mac 上通过的网页测试不等同于 Windows 安装验收。
