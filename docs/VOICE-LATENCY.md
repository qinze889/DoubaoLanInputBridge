# 实时语音延迟、后台工作控制与长期登录

2026-10-24，上海。豆包继续只提供 ASR/TTS，Chat 与 Work 使用本机 DeepSeek Harness；本次没有换成单独的云端聊天。

## 实际改动

- 本机在设备连接后预热固定版本 DSH SDK 运行时。连续对话复用进程与已打开 Session，不再每句重启 headless。保留16段活跃会话上限，超过时在没有执行轮次的边界关闭运行时，再按需恢复磁盘会话。
- SDK 协议没有单轮取消；声笺串行运行电脑操作。取消时先终止自己拥有的运行时进程组和子进程，再发回取消确认。下一轮通过 `session/resume` 修复并恢复会话，失败不自动重发旧指令。停止播报和插话仍不取消 Work。
- 有明确进度、取消、确认意图的语音，直接走控制接口，不等待模型推理，也不等待正在准备的照片。控制目标优先选择当前会话中正在执行的 Work，排队的新补充不会覆盖它。普通补充按顺序处理，页面明确显示排队；任务执行期间输入框可继续使用。
- 用户插话后分离旧回复显示与音频，后台仍订阅工作状态；完成、失败、取消等终态可汇报，迟到的旧聊天回复不重新播报。电脑操作继续受现有后台浏览器、后台控件权限和确认策略约束。
- 活跃 Harness Chat 的文字流采用上游已经验证的 low 思考档，减小任务分发与事件转发等待，首句分段等待从140毫秒降到80毫秒。未把“收到任务”的提示音当作模型首音。

## 首音数据与限制

[真实模型及 TTS 数据](research/VOICE-LATENCY-VALIDATION.json)每阶段3轮，从模拟“ASR 已完成”后的 API 提交，到真实 TTS 返回首个 PCM 数据包。基线中位数约3.25秒，常驻 SDK 约2.22秒，约减少32%；SDK 连续轮次测得约2.22和1.99秒。冷启动样本仍约3.92秒。

样本很小，模型缓存和上游负载会变化。这不是手机端说完到实际出声的完整时间，还需加上手机端点检测、ASR、网络和硬件播放；不承诺所有问题低于两秒，也不声称已达到豆包 App 的端到端延迟。看图和复杂工作还需要视觉／工具调用时间。

[真实后台进程验收](research/WORK-CONTROL-VALIDATION.json)：后台等待期间的进度接口约9毫秒返回，取消约136毫秒得到电脑确认，所属等待子进程已停止。取消后的下一轮成功恢复 Session，未重放旧操作。这是 HTTP 控制链路计时，不含 ASR/TTS。

## 扫一次后如何复用

同一手机浏览器登录后，直接打开固定地址 `https://test.xjiaoai.com/shengjian/api/v2/console`，可以收藏或添加到主屏幕，不必每次重新扫码。二维码票据仍是120秒、一次使用；它完成登录，之后依靠浏览器持有的 `Secure; HttpOnly; SameSite=Strict` Cookie 记住设备。

服务端会话与 Cookie 改为180天，使用期间滚动续期；旧的有效登录也会续期。重新打开页面会刷新 Cookie，长时间保持打开时每6小时刷新。旧二维码链接会优先恢复已有登录，不再先退出账号后兑换过期票据。临时断网保留待兑换票据在本页内存中，联网后重试；不写入持久 JS 存储。

更换浏览器、无痕模式、清除浏览器数据、主动退出、长期未使用到期、设备被撤销时需要重新登录，可用用户名／密码，无需一定回到电脑旁扫码。不同浏览器之间不会自动共享登录；浏览器自身清理 Cookie 的行为不受声笺控制。

## Mac 扫码入口与文件传输设置

连接手机页顶部的固定公网二维码用于实时语音、图片创作和电脑 Agent，不需要 `relay.json`。手机登录后可以继续使用同一固定入口。

“文件传输与自动粘贴”为默认收起的可选区域。其中“自建文件中转”属于旧文件传输服务，需要为本机独立签发的配置；它与账号语音入口的配置无关。未配置时点击只显示行内说明，保留当前传输方式，不再弹出阻塞对话框。菜单栏的连接开关也明确标为“文件传输”。
