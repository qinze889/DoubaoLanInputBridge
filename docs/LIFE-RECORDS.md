# 生活记录、WorkBuddy 看图和晚间记忆

入口：声笺账号区扫码登录后，在 WebUI 打开“生活记录”。原始记录按账号保存在云端独立 SQLite WAL，提炼后的记忆同步到同账号、具有任务授权的本机 Agent。原始图片和对话不会整批复制到电脑。

照片现在可以[即时语音聊图和开启相机预览](REALTIME-VISION.md)，晚间再把照片与问答一起整理。

## 使用

- 文字可“保存文字”，也可“聊一聊并记录”；助手回复同样保留。选图或手机拍照后，图片与当前正文自动进入时间线。
- 对话页产生的文字、语音转写和助手回复默认一起记录，可在设置中关闭。实时音频本身不归档；不自动采集屏幕、浏览器活动或其他应用内容。
- 默认每天 **23:00 / Asia/Shanghai** 整理当天记录，可修改时间、时区或关闭。服务恢复后补查前一天。相同日期及记录版本不会重复发起整理；23 点后增加记录会产生新版本。
- 可以主动“整理这一天”。“重新整理”明确发起新模型调用，可能再次扣额度；结果未知、失败或服务重启后不会自动重放同版本调用。
- 照片在每日整理时由所选 WorkBuddy 模型描述可见内容；默认 **`workbuddy/cn:glm-5v-turbo`**。页面顶部可切换识图模型，当前开放双图实测通过的 24 个 ID，见[完整实测列表](research/VISION-MODEL-VALIDATION.md)。识图描述与文字一起进入摘要和有来源的记忆。时间线上可查看照片描述。文字整理继续使用现有 DeepSeek 模型。
- 记忆可查看来源、修改和删除；人工修改和删除的主题不会被自动整理覆盖。删除原记录会撤回引用它的记忆，并清空该账号的既有派生摘要（保守处理，避免旧摘要留下被删内容）。
- 同账号本机 Agent 在线且桌面登录有效时，每分钟拉取一次完整记忆快照；云端删除也会撤回本机副本。可在 Mac / Windows Agent 的“生活记录沉淀的记忆”查看，任务是否使用它由“任务使用本地记忆”开关控制。离线保留上次快照；未登录、设备撤销或账号不匹配时清空副本。

## 数据与边界

- 云端：`<core-data>/life/life.sqlite3`、`<core-data>/life/images/`，不使用 sub-buddy、WorkBuddy 网关或旧传输业务数据库。
- 本机：原有 `<app-data>/agent/personal/personal.sqlite3` 的独立 `life_memories` 表，按已登记设备隔离。
- 浏览器：IndexedDB 按账号存待传记录和压缩图片，不存模型凭据；服务器确认后才删除待传项。上传和记录都有幂等 ID。只支持最近 30 天的离线补传，最多 500 条待传；浏览器清理站点数据会清除尚未同步的内容。
- 账号图片总量 200 MiB；单请求最多 8 MiB、单图最多 20 MP。服务端只接受 JPEG/PNG/WebP，归一为最长边 1600 的 JPEG 并去除 EXIF。浏览器拍照/HEIC 支持取决于设备解码能力。
- JSON 请求仍限制 128 KiB。图片路由先验登录，再读图；下载必须携带当前账号认证，不把 token 放进图片 URL。
- 单日最多 500 条 / 20 万文字，长日记分段提炼后合并。记忆最多 500 条。超限会明确失败，原始记录保留。当前检索是文字时间线查询与本地关键词相关性排序，未实现向量检索。
- 模型通过 `record_life_day` 函数约束输出，再校验结构、来源和记录版本。只接受当天用户记录作记忆来源，不将助手建议当成用户事实；照片不推断身份、健康、财务等敏感属性。模型输出无法解析时不写记忆，不用聊天正文冒充 JSON。
- 用量沿用预留、实际用量结算、明确拒绝释放机制；缺少用量或网络结果未知时保留预留，等待核对，不伪造费用。
- 删除撤回在线记录、图片和上下文；受保护的部署恢复点仍可能包含历史数据，应按服务器备份保留政策到期清理。SQLite WAL 和恢复点不等于密码学擦除。

## 参考与取舍

参考 [Memos](https://github.com/usememos/memos) 的个人时间线与附件组织、[附件文档](https://usememos.com/docs/usage/attachments) 的草稿/重试思路，以及 [Mem0 的记忆主流程](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py) 中原始内容提取、主题更新、删除和历史的分离。这里借鉴机制，按声笺账号、额度与 SQLite 约束自行实现，没有直接复制其代码、引入完整服务或把第三方登录态发给浏览器。
